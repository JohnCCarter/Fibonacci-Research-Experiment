# `/absorb-patterns`

**Purpose:** scan external repos / papers / tools / libraries for patterns that **strengthen** this
repo — **never replace** it.
**When to use:** when looking for methodology, tooling, visualization, labeling, or validation
patterns to adopt; mapping the external ecosystem to a concrete repo gap.
**Codifies:** the external-pattern-scan absorption discipline (absorb, never replace).

## Steps

1. Identify candidates (repos, papers, libraries) for the stated area.
2. Verify what each **actually does** from primary sources (README / code / tests / paper) — not
   hype or popularity.
3. Map each to a **concrete fib-repo problem** it would solve; drop any that can't be mapped.
4. Classify: **ABSORB NOW** / **STUDY LATER** / **INSPIRE ONLY** / **REJECT**.

## Output (per candidate)

- Source · domain · **observed / inferred / unverified** · pattern to absorb · mapped repo problem ·
  files likely affected · risks · ROI (Low/Med/High) · confidence (1–10) · next safe step.

## Non-goals

- No recommendation that **replaces** the repo, introduces **leakage**, turns **machine labels into
  truth**, encourages curve-fitting, or adds a heavy **dependency** without clear ROI.
- Keep it lean — a scan, not a governance/packet layer.
